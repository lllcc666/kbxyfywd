# 小游戏自动化工作流

本文件描述的是“任何卡布西游项目”里的通用自动化实现顺序，不依赖某个仓库的具体文件结构。

## 适用范围

适用于以下需求：

- 新增某个小游戏自动化
- 补齐某个周活动的发包与收包逻辑
- 把 AS3 分析结果落地到现有项目

## 实施顺序

### 1. 先识别活动协议

至少确认：

- 活动名称
- 活动 ID
- send / back opcode
- params
- 命令字符串
- 是否需要 `checkCode`
- 是否还有 `exchange` / `exchange_info`

### 2. 在当前项目中定位五个职责层

按职责找，不按固定文件名找：

1. 协议常量层
2. 构包 / 发包层
3. 收包 / 路由层
4. 状态层
5. UI / 消息入口层

### 3. 补协议常量

把以下信息放到当前项目的“协议常量层”：

- send opcode
- back opcode
- activity id
- 命令常量

如果项目里同时存在共享常量与兼容宏，两边都同步，避免漂移。

### 4. 补发送逻辑

在当前项目的发送层实现：

- 构包
- 发包
- 如果需要，等待响应
- 如果需要，自动化线程或循环

### 5. 补接收与路由

在当前项目的接收层实现：

- opcode 路由
- params 路由
- 响应 body 解析
- 状态更新

### 6. 补状态机

如果该活动不是单发单收，要补：

- 剩余次数
- 冷却
- `checkCode`
- 排名 / 积分 / 勋章
- 自动化停止条件

### 7. 补 UI 入口

若用户需要前端触发，再补：

- 按钮
- 消息入口
- 提示文本

### 8. 验证

至少验证：

1. 封包格式与 AS3 一致
2. 路由能收到对应响应
3. 自动化停止条件不会失控
4. UI 入口可正常触发

## 输出要求

完成后至少说明：

- 协议信息
- 当前项目改动点
- 依赖的 AS3 证据
- 已知风险
- 建议验证方式
