# 小游戏自动化工作流

本文件描述的是“任何卡布西游项目”里的通用自动化实现顺序，不依赖某个仓库的具体文件结构。

## 适用范围

适用于以下需求：

- 新增某个小游戏自动化
- 补齐某个周活动的发包与收包逻辑
- 把 AS3 分析结果落地到现有项目

## 实施顺序

### 1. 先识别活动协议

至少确认：

- 活动名称
- 活动 ID
- send / back opcode
- params
- 命令字符串
- 是否需要 `checkCode`
- 是否还有 `exchange` / `exchange_info`

### 2. 在当前项目中定位五个职责层

按职责找，不按固定文件名找：

1. 协议常量层
2. 构包 / 发包层
3. 收包 / 路由层
4. 状态层
5. UI / 消息入口层

### 3. 补协议常量

把以下信息放到当前项目的“协议常量层”：

- send opcode
- back opcode
- activity id
- 命令常量

如果项目里同时存在共享常量与兼容宏，两边都同步，避免漂移。

### 4. 补发送逻辑

在当前项目的发送层实现：

- 构包
- 发包
- 如果需要，等待响应
- 如果需要，自动化线程或循环

### 5. 补接收与路由

在当前项目的接收层实现：

- opcode 路由
- params 路由
- 响应 body 解析
- 状态更新

### 6. 补状态机

如果该活动不是单发单收，要补：

- 剩余次数
- 冷却
- `checkCode`
- 排名 / 积分 / 勋章
- 自动化停止条件

### 7. 补 UI 入口

若用户需要前端触发，再补：

- 按钮
- 消息入口
- 提示文本

### 8. 验证

至少验证：

1. 封包格式与 AS3 一致（字段顺序、个数、类型逐项对照 AS3 `readInt()` 顺序）
2. 路由能收到对应响应
3. 自动化停止条件不会失控
4. UI 入口可正常触发

注意：**编译通过不等于逻辑正确**。交付前对改动做一次只读 review，逐条对照 AS3 行号核对边界与回退链路；若无法本地实测，就把服务端真实 `result` 码回显到提示里，让用户回报即可定位。

## 实现期通用红线（高频踩坑）

以下每条都来自"照 AS3 写了却跑不通"的真实故障。判据永远是 AS3 状态机本身，不是"看起来合理"。

1. **一个主动包配一次等待，不要"发完即走"。** 底层等待只按 opcode + params 匹配、不认命令字符串；异步发出的包若无人消费，它的回包会被后续请求误当成目标响应，导致等待标志永不清除、查询假死超时。
2. **等待标志要在 body 解析完成之后才清除**；解析前的提前 return 不能顺手清标志。
3. **响应分发按"期望操作"过滤**：只接受与当前等待匹配的那一个，迟到的回包直接丢弃，避免用上一轮的旧状态判断本轮结果。
4. **多阶段（分关 / 连续挑战）活动照 AS3 的状态迁移写**：进入下一阶段时客户端通常**继续沿用同一会话的校验种子**，只有服务端重新下发才覆盖 → 不要自己先清零；也不要用上一包回包的 result 当"能否进入下一阶段"的闸门（AS3 对非 0 结果往往只提示、流程照走）。
5. **收尾包（关闭 / 放弃本局）的发送条件逐字照抄 AS3**：漏发会自锁（后续开局一直返回"在游戏中"），多发会被服务端当成"放弃本局"而降级成绩。
6. **各操作的放行门槛回到对应 Model 的 `readInt()` 顺序逐字段核对**：字段偏移或顺序错一位，校验式就全错 → 服务端只扣次数不发奖励；**宁可少判也不要多判**（不要额外加"看起来更严格"的条件）；有的活动首字段是 result，有的首字段直接是勋章数，按各自的 AS3 判据走。
7. **校验式（checkCode / end_code）原样实现**：位运算、取模、乘法因子、32 位整数回绕都要一致；任一因子为 0 属于无效结算，应提前拦下，而不是发出一个必错的包。
8. **次数与冷却以服务端回包为准**：每轮结束重查一次、活动退出前再强制重查一次，保证 UI 显示权威值；"次数未减少"先短暂重查再判失败；短冷却循环等待（可中断）后继续，长冷却才跳过，不要一见冷却就结束整个活动。
9. **并发与可中断**：同一响应通道（同 opcode + params 路由到同一 handler）的多个流程必须互斥；批量执行单线程串行；所有长循环都要检查可中断标志。
10. **预置条件先校验、失败要能读懂**：未连接游戏或用户 ID 未就绪时直接拒绝执行，不要盲目发包等超时；失败提示带上服务端真实 `result` 码。

## 输出要求

完成后至少说明：

- 协议信息
- 当前项目改动点
- 依赖的 AS3 证据
- 已知风险
- 建议验证方式
